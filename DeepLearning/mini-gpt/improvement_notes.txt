The base model was underfitting. Phrases like "the first X of the Y" kept repeating. Val loss plateaued before train loss caught up. 7M params just isn't enough for WikiText-2. So I scaled up the model for the improved version. I kept the architecture and code the same as the base, so the graders test the same implementation.
Bigger model. I doubled d_model (128 to 256) and num_heads (4 to 8). Each head still has dim 32, so the attention math is the same. num_layers went from 4 to 6, and d_ff from 512 to 1024. The total ended up at 17.6M params, about 2.4x the base. Most of that comes from the token embedding. With weight tying, embed and lm_head share one big (vocab x d_model) matrix that grows with d_model. I added both width and depth instead of going extreme in one direction. I wasn't sure which the model needed more, so changing both felt like a safer bet.
Longer context. block_size went from 128 to 256. When I looked at the base model's inputs, 128 tokens often cut off sentences mid-clause. The model was predicting without much real context. Doubling the window gives each prediction twice as much history.
More regularization. Dropout 0.1 to 0.2, weight decay 0.01 to 0.1. With 2.4x the params on the same small dataset, the base regularization was too weak. Train loss kept dropping but val stalled. I tried 0.15 dropout first. 0.2 gave a cleaner curve.
Longer training. 25 epochs instead of 15. I dropped batch size to 32 so the bigger model and longer sequences fit in T4 memory. I raised peak LR to 5e-4 because longer cosine schedules usually want a slightly higher peak. Optimizer, gradient clipping, and train.py / generate.py are the same.
What I didn't change. Tokenizer, LMDataset, causal mask, Pre-LN structure, weight tying, sinusoidal positions. All the same as the base. The "improvement" is just different hyperparameters.
Results. The base checkpoint hit test ppl 269.63, matching the reference run. The improved checkpoint reached best val ppl 168.71 at epoch 12. Final test ppl was 183.38. That is a 32% drop in test ppl from the base. Most of the gain came from scaling up the model. The longer context and extra epochs added smaller but steady improvements. One thing I noticed in the training log: val loss bottomed out at epoch 12, then drifted slightly up through epoch 25. So the model was starting to overfit, even with more dropout. Next time I would use early stopping or save the best val checkpoint instead of the final one. On this run, that would probably save another 5 to 10 test ppl. The generated text also got better. The model now stays roughly on topic across a paragraph and makes Wikipedia-style section headers. It still does not produce factually correct text.
